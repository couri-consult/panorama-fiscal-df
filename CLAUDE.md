# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Single-page dashboard ("Panorama Fiscal do DF") that visualizes fiscal indicators for the Brazilian Federal District (Distrito Federal). The dashboard itself is a static `index.html`; data is generated offline by Python scripts that pull from public APIs and a small manual XLSX, producing a `data.json` consumed at runtime by the page.

- **Live site:** https://couri-consult.github.io/panorama-fiscal-df/
- **Repo:** `couri-consult/panorama-fiscal-df` (GitHub Pages serves the `main` branch root)

### Runtime flow (browser)

1. `index.html` does `fetch('data.json')`.
2. Each top-level key in `data.json` (mirrors the old sheet names) is passed to a `renderXxx` function.
3. Chart.js draws charts (loaded via CDN). SheetJS is **no longer needed**.

### Build flow (Python, runs locally)

`python scripts/build_data.py` orchestrates:
1. Load `manual/panorama_manual.xlsx` as the baseline for every section.
2. Override sections with API/CSV data where available (CAPAG, IBGE, SICONFI RREO/RGF, Portal da Transparência).
3. Compute derived KPIs (e.g. investimento/RCL).
4. Write `data.json` to the project root.

**Resilience pattern:** Every API call is wrapped in `safely(...)` which falls back to the manual XLSX value if the call fails or returns empty. The dashboard always renders something.

### data.json shape

Mirrors the previous Excel sheet names for backward compatibility with the renderers in `index.html`. Top-level keys:

| Key | Renderer | Columns / fields |
|---|---|---|
| `kpis` | `renderKpis` | `chave`, `valor_bilhoes`, `sub`, `cor`. `chave` ∈ {orcamento_df, fcdf, investimento_rcl, capag, caixa, beneficios} |
| `investimentos` | `renderInvestimento` | `estado`, `pct`, `ranking`, `destaque` (ranking of all 27 UFs + média BR) |
| `caixa` | `renderCaixaChart` | `ano`, `caixa_liquido`, `nao_vinculado` (in reais; 5 anos from RGF Anexo 05) |
| `capag` | `renderCapag` | `indicador`, `nota`, `badge`, `valor`, `obs`, `conceito` (3 current indicators) |
| `capag_historico` | `renderCapagHist` | `ano`, `endividamento`, `poupanca`, `liquidez`, `consolidado` (2018–latest) |
| `pessoal` | `renderPessoal` | `chave`, `valor` — keys: atual_pct, alerta_pct, prudencial_pct, maximo_pct, rcl_bi |
| `clp_ranking` | `renderCLP` | `indicador`, `posicao`, `conceito` |
| `ppps` | `renderPPPs` | `nome`, `status` ("A contratar" / "Suspenso" / "Contratada") |
| `ppps_projecao` | `renderPPPProj` | `ano`, `despesas_ppp`, `rcl`, `pct` |
| `_meta` | (not rendered) | `updated_at`, periods, populacao_df, raw_siconfi, fcdf_dotacao_atualizada, `sources` |

`_meta.sources` shows the provenance of each key/sub-key (`manual`, `csv-local`, `siconfi-rreo-atual`, `portal-transparencia-scrape`, etc.) — useful for debugging.

### O que cada aba do `manual/panorama_manual.xlsx` contribui

Após a limpeza de 18/05/2026, o manual contém **só o que o painel realmente lê**:

| Aba | Colunas usadas | Função |
|---|---|---|
| `kpis` | `chave`, `valor_bilhoes`, `sub`, `cor` | Define a ordem dos 6 KPIs. Para `orcamento_df`, `fcdf`, `investimento_rcl`, `capag`, `caixa` os valores são sobrescritos pela API (linhas servem só de anchor). **`beneficios` é a única linha com valor manual editável**. |
| `investimentos` | `estado`, `pct`, `ranking`, `destaque` | Ranking dos 27 UFs (manual integral) |
| `capag` | `indicador`, `obs`, `conceito` | Textos descritivos — `nota`/`valor` vêm do CSV |
| `pessoal` | `chave`, `valor` | Apenas limites LRF (`alerta_pct`, `prudencial_pct`, `maximo_pct`). `atual_pct` e `rcl_bi` são adicionados pela API. |
| `clp_ranking` | `indicador`, `posicao`, `conceito` | 9 indicadores do CLP Pilar Solidez Fiscal |
| `clp_meta` | `chave`, `valor` | `pos_geral` (texto p/ posição no pilar), `pos_geral_obs`, `ano_ranking` |
| `ppps` | `nome`, `status` | Lista de PPPs (contratadas / a contratar / suspenso) |
| `ppps_projecao` | `ano`, `despesas_ppp`, `rcl`, `pct` | Projeção plurianual |

## SICONFI specifics (lessons learned)

- **Entidade do DF**: usar `id_ente=53` (cod_ibge da UF). NÃO usar 5300108 — esse é Brasília como **município** (esfera M).
- **Documento de referência**: `Cod_instituicoes_siconfi.pdf` (no site siconfi.tesouro.gov.br). DF Executivo aparece como `53EX`, cod_ibge 53.
- **Rate limit**: o Oracle ORDS pool retorna HTTP 429 frequentemente. `_http.py` faz retry com backoff exponencial. `siconfi.py` adiciona um `time.sleep(3)` entre chamadas.
- **MCASP atual vs antigo**: a numeração das linhas mudou. Linha que o usuário pode chamar de "(VIII)" no RREO antigo corresponde a `TotalDespesas (XII)` no formato atual. Vide `extract_rreo_balanco` em `siconfi.py`.
- **RGF Anexo 05**: o `cod_conta` é `DisponibilidadeDeCaixaLiquidaAposRP` (com `AposRP` no final). O label da linha TOTAL mudou entre 2022 (`TOTAL (III) = (I + II)`) e 2023+ (`TOTAL (IV) = (I + II + III)`) — `extract_rgf_caixa` trata os dois.

## Portal da Transparência specifics

- **Token**: requer registro em https://portaldatransparencia.gov.br/api-de-dados/cadastrar-email com selo gov.br Prata ou Ouro. Token é enviado por email. Pedir mais de uma vez **invalida o anterior**.
- **Token storage**: arquivo `.env` (gitignored). Variável `TRANSPARENCIA_TOKEN`. `build_data.py` carrega via `_load_dotenv()`.
- **LOA / dotação atualizada**: a API `/api-de-dados` só expõe empenhado/liquidado/pago. Para a dotação atualizada do FCDF (mostrada na página `/orgaos/25915-...`) usamos web scraping em `fetch_fcdf_dotacao_atualizada()`. Frágil a mudanças de layout — se quebrar, ajustar o regex.

## Running / developing

```bash
# Setup (uma vez)
pip install requests openpyxl pandas pypdf
# Criar .env com TRANSPARENCIA_TOKEN (não commitar)
echo "TRANSPARENCIA_TOKEN=<seu_token>" > .env

# Atualizar dados
python scripts/build_data.py

# Ver localmente
python -m http.server 3000
# → http://localhost:3000

# Publicar
git add data.json [outros arquivos modificados]
git commit -m "atualiza dados"
git push
```

GitHub Pages republica em ~30-90s após o push. Para forçar reload no browser: ctrl+shift+R.

## Conventions

- All UI copy and data labels are in Portuguese (pt-BR). Preserve the language when editing.
- Color system lives in `styles/tokens.css` (CSS variables) — reuse them rather than adding new hex values.
- Keep the single-file structure of `index.html`; do not introduce a bundler or framework.
- Python: stdlib + `requests`, `openpyxl`, `pandas`. No build, no virtualenv enforcement. Type hints optional but welcome.
- Number formatting: Brazilian style (`.` for thousands, `,` for decimal). `_parse_br_number()` in `transparencia.py` handles strings; `num()` in `index.html` handles them in JS.
